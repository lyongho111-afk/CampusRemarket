# 캠퍼스 리마켓 v11 — 학생·사장·관리자 독립 사이트

**학생용 사이트는 v10 화면 그대로 유지하고, 사장용·관리자용 사이트 2개를 추가했습니다.** 기존 학생 HTML/CSS/JS/템플릿 36개는 v10 통합본과 SHA-256이 동일합니다.

세 사이트는 각각 다른 주소, 첫 화면, 메뉴, 로그인 세션, 웹 실행 프로세스를 가집니다. 화면만 세 개의 탭으로 나눈 구성이 아닙니다. 회원·가게·거래·평가 DB와 인증 API는 한 곳에 두어 데이터를 공유합니다.

## 빠르게 실행
ZIP 전체를 새 폴더에 풀고 **세사이트_모두실행.cmd**를 실행하세요. 8080/8081/8082 포트를 사용 중인 이전 서버는 직접 종료한 뒤 실행합니다. 실행기는 다른 프로그램을 종료하지 않습니다.

| 사이트 | 로컬 주소 | 로그인 |
|---|---|---|
| 학생 | http://localhost:8080/ | 학교 인하대학교 / 학번 20261234 |
| 사장 | http://localhost:8081/ | owner1 |
| 관리자 | http://localhost:8082/ | admin1 (또는 admin2, admin3) |

시연 공통 비밀번호: **campus1234!**. 매니저 계정 manager1도 사장 사이트에서 로그인할 수 있습니다.

시작이 끝나면 실행 창에 세 주소가 출력됩니다. 해당 창에서 Ctrl+C를 누르면 실행기가 시작한 세 프로세스를 종료합니다. 서버 로그는 logs 폴더에 저장됩니다. 서버가 시작되지 않으면 해당 로그를 확인하세요.

## 각각 따로 실행
1. 기존 **실행하기.cmd**: 학생 사이트와 공통 API/DB를 시작합니다 (8080).
2. **사장사이트_실행.cmd**: 독립 사장 웹 서버를 시작합니다 (8081). 공통 API 8080이 먼저 실행되어 있어야 합니다.
3. **관리자사이트_실행.cmd**: 독립 관리자 웹 서버를 시작합니다 (8082). 공통 API 8080이 먼저 실행되어 있어야 합니다.

각 사이트는 별도로 로그인합니다. 동일한 브라우저/호스트에서 열어도 학생 JSESSIONID, 사장 CAMPUS_OWNER, 관리자 CAMPUS_ADMIN 쿠키를 분리하여 다른 사이트의 로그인/로그아웃에 영향을 주지 않습니다. 사장 사이트 서버만 재시작해도 공통 DB 서버와 학생/관리자 사이트는 유지할 수 있습니다.

기존 학생 로그인 화면과 이동 방식은 변경하지 않았습니다. 새 사장·관리자 사이트는 각 주소로 직접 접속하세요. 사장 신규 회원가입은 학생 사이트의 기존 signup.html을 사용한 뒤 사장 사이트에서 로그인합니다.

## 사장 사이트
- 대시보드: 가게 영업 상태, 공개 상태, 여유 공간, 매니저 수, 학생에게 보이는 가게 정보.
- 가게 정보: 가게명·업종·전화·영업시간·예약·공간·메뉴 수정. 대표자/사업자번호는 실제 사장 계정에서 가져옵니다.
- 영업 관리: 영업중/혼잡/영업종료/휴무, 영업시간·여유 공간·휴무·메뉴·학생 혜택 변경.
- 매니저 관리: 기존 팀원 API로 최대 3명 등록·삭제. 매니저는 운영 정보만 변경할 수 있고 가게 기본 정보·새 가게 등록·매니저 관리는 사장만 가능합니다.
- 신규 가게 등록: 해당 사장에게 한 곳을 연결하며 관리자 승인 전에는 학생 사이트에 공개되지 않습니다.

기본 owner1과 manager1은 기존 예시 카페에 연결됩니다. 이 연결은 명시적인 시연 초기화 기능이며 `campus.portal.seed-demo-shop=false`로 끌 수 있습니다. 실제 새 사장에게 다른 사장의 가게를 자동 연결하지 않습니다.

## 관리자 사이트
- 대시보드: 실제 회원/가게/거래 완료/평가 수, 최근 7일 주문 등록, 확인할 가게, 최근 회원.
- 회원 관리: 이름·아이디·학번·학교·이메일 검색, 역할 필터, 상세 조회. 비밀번호 조회·역할 임의 변경·회원 삭제 기능은 제공하지 않습니다.
- 가게 관리: 가게 조회, 사장 배정/해제, 승인·공개 중지. 사장만 배정할 수 있고 사장당 한 가게를 보장합니다.
- 거래 현황: 상태 필터, 상품·주문·구매자·판매자·약속 금액·장소 조회. 관리자 임의 결제/거래 상태 변경 기능은 추가하지 않았습니다.
- 매너온도 평가: 평가자·상대방·GOOD/BAD·실제 증감량·평가일 조회. 평가/온도 조작 기능은 추가하지 않았습니다.

## 데이터 연결 확인
1. 사장 사이트에서 영업 상태·메뉴를 저장합니다.
2. 학생 사이트의 가게 탭을 새로고침하면 저장한 공개 정보가 반영됩니다.
3. 새 사장의 가게는 관리자 사이트에서 승인해야 학생 사이트에 표시됩니다. 공개 중지하면 학생 목록과 상세에서 숨겨집니다.
4. 관리자 화면은 새로고침 버튼으로 최신 정보를 불러옵니다. 거래/평가는 기존 학생 기능으로 발생한 데이터를 조회합니다.

## 소스 구조
- 학생: 기존 static/preview, templates, 학생 Controller/Service/MyBatis 기능 유지.
- 사장 프런트: `src/main/resources/portal-sites/owner/` (index.html, styles.css, common.js, app.js).
- 관리자 프런트: `src/main/resources/portal-sites/admin/` (동일 구성, 별도 디자인·메뉴·코드).
- 공통 관리 API: `src/main/java/com/campus/remarket/portal/`.
- SQL: `mappers/PortalShopDao.xml`, 기존 ShopDao resultMap에 ownerMemberId 추가.
- 독립 웹 서버: `src/main/java/portal/campus/PortalGatewayApplication.java` 및 PortalGatewayController.
- 로컬 전체 실행기: `portal/campus/StartSites.java`.

독립 웹 서버는 자기 프런트만 제공하고 /api 요청을 공통 API로 전달합니다. 데이터베이스 연결/회원 엔티티/초기 데이터 생성은 공통 서버만 담당합니다. 게이트웨이는 DataSource 자동 구성을 제외하므로 별도 DB를 만들거나 초기화하지 않습니다. API 목적지는 portal.backend로 설정합니다.

JAR 하나에 세 실행 진입점을 묶어 중복 배포 파일을 줄였습니다. 실행 프로세스와 사이트는 별도이며, 다른 컴퓨터에서 사장/관리자 웹 서버를 실행할 때에도 접근 가능한 공통 API 주소를 지정할 수 있습니다.

## 빌드와 JAR 교체
JDK 25 / Spring Boot 4.0.2 / Gradle 9.3.0을 유지합니다.

```bat
gradlew.bat test bootJar
copy /Y build\libs\campus-remarket-mybatis-0.0.1-SNAPSHOT.jar app\campus-remarket.jar
```

소스를 수정하면 JAR를 교체한 후 사용하는 공통/사장/관리자 프로세스를 다시 시작하세요. 이번 ZIP은 최신 소스와 실행 JAR가 일치합니다. Java 실행 환경과 Gradle Wrapper는 포함하고 build/.gradle/.idea/로그/실제 키 설정은 제외했습니다.

게이트웨이를 IntelliJ에서 실행할 경우 PortalGatewayApplication.main을 선택하고 프로그램 인수에 `--portal.site=owner --server.port=8081 --portal.backend=http://127.0.0.1:8080` 또는 admin/8082를 지정합니다. 공통 서버는 기존 CampusApplication.main입니다.

## 기존 회원 소스 변경
v10 대비 팀원 MemberController.java에는 **로그인할 때 staffCsrf 토큰을 초기화하는 한 줄**만 추가했습니다. 최초 회원 ZIP과 비교하면 기존 변경인 MemberService.java, MemberController.java, member.js 총 3개 파일이며 전체 diff와 원본 해시를 docs에 함께 제공합니다. 회원 HTML/CSS 및 나머지 Java 파일은 원본을 유지합니다.

## 검증과 범위
- 기존 학생/회원/평가 테스트 24개 + 새 관리 API 테스트 6개 = **30개 성공**.
- 실행 JAR로 서로 다른 세 프로세스/주소 시작, 동일 브라우저의 사장·관리자 로그인 쿠키 분리와 독립 로그아웃, 운영 정보의 학생/관리자 반영 확인.
- 브라우저에서 두 사이트의 로그인·대시보드·회원 역할 필터·가게 배정 폼·매니저 등록 폼·운영 정보 저장을 확인했습니다. 반응형 CSS를 포함하되 모바일 실기기 테스트는 수행하지 않았습니다.
- 새 관리 API는 역할 검사와 CSRF 토큰을 사용합니다. 사장/매니저의 가게는 세션에서 결정하므로 요청한 다른 가게 ID로 접근할 수 없습니다.
- 공유 설정은 config/portal-links.example.properties를 참고합니다. 설정 파일이 없으면 표의 localhost 주소를 사용합니다.
- 새 사장·관리자 사이트를 외부 공개하려면 해당 공개 방식의 승인이 필요합니다. 이 ZIP 자체에는 공개 터널이나 로그인 정보를 외부로 전송하는 기능을 자동 실행하지 않습니다.

기본 DB는 메모리 H2이며 공통 서버 종료 시 새 회원·가게·거래·평가가 초기화됩니다. 외부 메일 발송/지도 키/Toss 실제 승인 등 기존 미연결 항목과 ±0.1도 임시 평가 정책은 그대로입니다. 이전 v10 문서는 이력이며 현재 사이트 구성은 이 README가 기준입니다.
