# v11 변경 내역 — 사장·관리자 독립 사이트 추가

v10 로그인 통합본을 보존하고 새 작업본을 만들었습니다. 기존 학생 화면/자산/템플릿 36개는 바이트 단위로 동일합니다.

## 새 프런트 2개
portal-sites/owner: 녹색 사장센터, 가게/운영/매니저 관리와 전용 로그인.
portal-sites/admin: 청색 관리자센터, 대시보드/회원/가게 승인·배정/거래·평가 조회와 전용 로그인.

주소, 메뉴, 로그인 쿠키, 웹 실행 프로세스를 분리했습니다. 공통 API/DB만 공유합니다. 각 프런트의 소스 디렉터리도 분리했습니다.

## 공통 서버 추가
- StaffAccess: 실제 회원 세션의 사장/매니저/관리자 권한 검사, staffCsrf 발급·검사.
- StaffPortalService/Controller/ErrorAdvice: 사장 대시보드·자기 가게 등록/수정·운영, 관리자 전체 현황·사장 배정·가게 승인/공개 중지.
- PortalShopDao/XML: 위 작업의 MyBatis SQL. member_id를 브라우저 입력으로 신뢰하지 않고 현재 사장 또는 관리자가 검증한 OWNER ID만 사용합니다.
- PortalDemoSeed: 실제 신규 계정은 임의 연결하지 않고 시연 owner1만 기존 예시 카페에 배정. 설정으로 해제 가능.
- PortalDirectory: 각 사이트 링크 설정 조회. 기본 localhost 포트는 8080/8081/8082.

## 기존 파일 변경
- ShopDto: ownerMemberId 추가.
- ShopDao.xml: owner_member_id resultMap 추가. 기존 CRUD 인터페이스는 유지.
- schema.sql, 참고 H2/MySQL DDL: shops.owner_member_id BIGINT UNIQUE 추가. 기존 가게 컬럼을 삭제하지 않음.
- data.sql: 기존 예시 카페만 공개(checked=true)로 초기화. 새 등록은 미승인으로 저장.
- ShopApiController: 승인된 가게만 학생 공개 목록에 포함.
- ShopController: 미승인 가게의 학생 상세는 404.
- 팀원 MemberController.java: 로그인 시 session.removeAttribute("staffCsrf") 1줄 추가. v10의 학번 세션/세션 ID 교체/로그아웃 무효화 유지.

## 별도 실행
- PortalGatewayApplication: 사장·관리자 웹 서버 진입점. 자기 정적 파일만 제공하고 /api를 공통 서버로 전달. DataSource를 구성하지 않음.
- PortalGatewayController: 사장/관리자 쿠키 분리, 다른 관리 사이트 경로 차단, 외부 Origin 쓰기 차단, 요청 크기 제한, HTTPS 쿠키 Secure 처리.
- StartSites 및 세사이트_모두실행.cmd: 로컬 세 프로세스 시작/준비 확인, Ctrl+C로 자신이 시작한 프로세스만 종료. 기존 포트가 사용 중이면 중단하며 다른 사용자 서버를 종료하지 않음.
- 사장사이트_실행.cmd, 관리자사이트_실행.cmd: 각각 독립 실행. 기존 실행하기.cmd는 유지.
- 실행 app/campus-remarket.jar를 최신 빌드로 교체.

## 검증
기존 24개 회귀 테스트 + 새 StaffPortalTests 6개 모두 성공. 새 테스트는 비로그인/학생/타 역할 차단, 비밀 필드 제외, 매니저 운영 범위, CSRF, 새 가게 승인 및 공개 반영, 잘못된 역할 배정 차단, 이전 사장의 접근 상실, 입력 길이 검사를 다룹니다.

독립 JAR 실행과 사장/관리자 세션 분리·독립 로그아웃, 공통 DB 반영, 브라우저 화면·폼·필터·저장도 검증했습니다. 학생 화면 SHA-256 보존 명세와 최초 회원 ZIP 대비 전체 diff를 포함합니다.

현재 회원/거래/평가 관리는 조회 위주이며, 가게 승인·배정과 사장 운영 정보는 실제 저장 기능입니다. 관리자 회원 삭제/역할 변경/결제 취소·정산/평가 조작 기능은 추가하지 않았습니다. 기본 H2 메모리 정책은 그대로입니다.
