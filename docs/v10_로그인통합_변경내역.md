# v10 로그인 통합 변경 내역

기존 로그인 통합본과 인계서의 실제 v10 MyBatis 프로젝트를 합쳤습니다. 인계서의 ZIP과 사용자가 압축을 푼 소스는 src 파일들이 동일함을 확인했습니다. 두 원본 ZIP과 IdeaProjects 아래 작업본은 수정하지 않았습니다. 전달 ZIP이 최신 단일 통합 프로젝트입니다.

## 최초 회원 ZIP에서 수정된 파일: 총 3개

1. **member/service/MemberService.java**: StudentMemberLink 생성자 주입. 학생 회원가입 시 저장한 Member를 student에 연결하고, 성공 로그인 시 기존 학생을 연결합니다. 로그인 메서드에 @Transactional을 추가하여 첫 연결이 가능하게 했습니다. 회원가입과 학생 연결이 같은 JPA/JDBC 트랜잭션에 참여하며 충돌 시 함께 롤백합니다. 이름·비밀번호·이메일·역할 검사 로직은 그대로입니다.
2. **member/controller/MemberController.java**: 로그인 성공 시 기존 loginMemberId와 함께 학생의 실제 학번 String을 loginUnisno로 저장합니다. 직원 계정으로 전환하면 학생 식별자를 제거하고, 이전 loginStudent와 평가 CSRF 토큰을 초기화합니다. 기존 세션 ID 교체와 로그아웃 세션 무효화는 유지했습니다.
3. **src/main/resources/static/member.js**: 이전 통합과 동일하게 학생/매니저/관리자 로그인 후 이동 주소를 `/api/members/me`에서 `/`로 변경했습니다. 사장의 manager.html 이동은 유지했습니다.

앞의 두 Java 파일 경로는 `src/main/java/demo/campus/campusremarketmember/`를 기준으로 합니다. 나머지 회원 Java 19개, 회원 HTML 3개, CSS 1개는 최초 ZIP과 바이트 단위로 같습니다. 정확한 변경 줄은 `팀원파일_전체변경.diff`에 있습니다. 기존 MemberPageConfig의 응답 변환을 통해 마켓 복귀 링크를 보여 주며 저장된 회원 HTML은 수정하지 않았습니다.

## v10/마켓 연결
- student의 unisno String, temp INT DEFAULT 365와 DTO/DAO/XML/Service/Controller 평가 구조를 유지했습니다.
- StudentDto/StudentDao.xml/schema.sql 및 참고 H2/MySQL DDL: 실제 JPA 회원에 대한 member_id 유일 연결 컬럼 추가. 기존 학생 컬럼은 삭제하지 않았습니다.
- StudentMemberLink 추가: 신규 가입/기존 학생 첫 로그인 연결, 온도 유지, 중복 학번의 다른 회원 소유권 침해 차단. 외부 회원 테이블의 FK DDL은 JPA 초기화 순서와 충돌하지 않도록 자동 생성하지 않고 실제 연결과 UNIQUE로 검증합니다.
- MarketMember: 학생 actorKey를 member:번호 대신 실제 학번으로 통일. 상품/거래 쓰기는 학생만 허용합니다. 직원 계정의 회원관리·게시판 사용은 유지합니다.
- RatingSession: loginMemberId로 실제 Member를 다시 확인하고 loginUnisno와 일치하는 학생만 평가자로 인정. loginUnisno/loginStudent 값만 있는 가짜/시연 세션은 인정하지 않습니다. demo-buyer 대체 계정을 제거했습니다.
- ProductApiController/SalesController, TradeApiController/TradeController: 실제 학번 판매자/구매자, 기존 소유권 검사 유지.
- TradeController: 거래 참여자 검사 뒤 v10 평가 상태/CSRF를 HTML 상세에 제공.
- MannerRatingApiController/MannerRatingController: 실제 로그인 거래 참여자만 상태 조회/저장. 기존 CSRF·트랜잭션·행 잠금·평가 UNIQUE·완료 상태 검사 유지.
- MannerRatingService, MannerRatingDao, 평가 Mapper, 온도 계산 VIEW는 v10 원본 규칙을 유지했습니다. 주문 완료 문자열 두 종류를 모두 인정합니다.
- 기존 카드의 loadData, productDetail, integrations-live 및 HTML에 v10 온도/완료/평가 연결을 합쳤습니다. 0도를 36.5도로 덮어쓰지 않도록 nullish fallback도 유지했습니다.
- session.js/features.js/app.js: 회원 학번 기준 내 판매글 필터, 학생 거래 안내, 세션 조회 이후 해시 경로 복원. preview/index.html에도 평가 스크립트를 연결했습니다.
- campus.demo-user-enabled=false. 인증 클래스 자체에도 시연 대체 계정으로 돌아가는 분기가 없습니다.
- 기본 ±0.1도 정책과 온도 범위는 변경하지 않았습니다.
- 실행용 app/campus-remarket.jar를 이번 소스로 다시 빌드한 JAR로 교체했습니다. 기존 실행하기.cmd와 Java runtime은 그대로입니다.

## 보존과 미포함 범위
기존 예시 글/주문은 예시 작성자 ID로 보존하여 실제 회원에게 자동 배정하지 않았습니다. 학교별 동일 학번은 단일 PK 계약상 충돌하면 409로 차단하며, 복합키 확장은 조별 정책 결정 사항입니다. 사장/매니저 아이디는 student 학번으로 등록하지 않습니다. 가게 관리 연동, 실제 이메일 발송, 운영 DB 마이그레이션, 실제 결제 승인 검증은 이번 작업에 추가하지 않았습니다. 기본 DB는 서버 재시작 때 초기화되는 메모리 H2입니다.
