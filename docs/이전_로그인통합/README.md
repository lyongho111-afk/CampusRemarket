# 캠퍼스 리마켓 로그인 통합본

두 번째 `campus-remarket-student-v9-mybatis.zip` 프로젝트에 첫 번째 `campus-remarket-member.zip`의 회원 기능을 통합했습니다. 두 입력 ZIP은 수정하지 않았습니다.

## 실행
1. 이 ZIP 전체를 새 폴더에 압축 해제합니다.
2. `실행하기.cmd`를 실행합니다. 포함된 Java 실행 환경과 **이번 소스로 새로 빌드한** `app/campus-remarket.jar`가 사용됩니다.
3. 서버 시작 후 http://localhost:8080/ 에 접속합니다. 상단 `로그인` 또는 http://localhost:8080/login.html 로 이동합니다.
4. 회원가입은 http://localhost:8080/signup.html 입니다. 사장 로그인 후에는 기존 팀원 화면인 매니저 관리 화면으로 이동합니다. `마켓으로 돌아가기` 링크로 메인 화면을 열 수 있습니다.
5. 서버 종료: 실행 창에서 Ctrl+C. 포트 8080을 사용하는 다른 프로그램이 있다면 먼저 해당 프로그램을 종료하세요.

## 테스트 계정
공통 비밀번호: `campus1234!`

| 종류 | 학교 선택 | 학번 / 아이디 |
|---|---|---|
| 학생 | 인하대학교 | 20261234 |
| 사장 | 사장님·매니저·관리자 | owner1 |
| 매니저 | 사장님·매니저·관리자 | manager1 |
| 관리자 | 사장님·매니저·관리자 | admin1 / admin2 / admin3 |

학교는 화면에서 이름으로 선택하세요. 번호는 학교 목록 API에서 동적으로 조회합니다.

## 원본 보존과 변경
- 팀원의 회원 Java 파일 21개, HTML 3개, CSS 1개는 원본과 바이트 단위로 같습니다.
- 팀원 파일 중 `src/main/resources/static/member.js` 한 파일에서 로그인 성공 후 이동 주소만 변경했습니다. 학생·매니저·관리자: `/api/members/me` → `/`. 사장: 기존대로 `manager.html`.
- 세 회원 HTML 파일의 저장 내용은 변경하지 않았습니다. 추가한 `MemberPageConfig`가 브라우저로 전송할 때 별도의 `member-navigation.js`를 연결해 마켓 복귀 링크를 표시합니다.
- 첫 번째 프로젝트의 별도 실행 클래스와 Gradle/DB 설정은 중복 적용하지 않았습니다. 실행 클래스는 기존 `com.campus.remarket.CampusApplication` 하나를 사용합니다.
- 구체적인 변경 사항: `docs/로그인통합_변경내역.md`. 팀원 파일의 실제 변경 diff와 SHA-256 비교표도 docs 안에 있습니다.

## IntelliJ / Gradle
프로젝트 폴더 또는 `build.gradle`을 Open하여 Gradle 프로젝트로 가져옵니다. Project SDK와 Gradle JVM은 JDK 25로 설정하고 `CampusApplication`을 실행하세요.

```bat
gradlew.bat test bootJar
gradlew.bat bootRun
```

Spring Boot는 두 번째 프로젝트 버전인 **4.0.2**를 유지했습니다. 회원은 팀원 코드 그대로 JPA, 마켓은 기존 MyBatis XML을 사용하고 하나의 H2 DataSource에 연결합니다. JPA 의존성과 BCrypt 암호화 의존성을 추가했습니다.

`build`, `.gradle`, `.idea`는 소스가 아니라 빌드 결과·캐시·IDE 설정 폴더입니다. 없어도 됩니다. IntelliJ에서 프로젝트를 열거나 Gradle 빌드를 실행하면 필요한 항목이 생성됩니다. `build.gradle`, `gradle/wrapper`, `gradlew`, `gradlew.bat`는 포함되어 있습니다. 최초 소스 빌드에는 의존성 다운로드용 인터넷과 JDK 25가 필요합니다. `실행하기.cmd`는 포함된 실행 환경으로 바로 실행합니다.

## 연결한 동작
- 로그인 전: 상품·게시글·가게 조회, 로그인·회원가입.
- 로그인 후: 회원 이름·로그아웃 표시, 본인의 판매글 등록·수정·삭제·할인·끌어올리기, 본인 게시글 수정·삭제.
- 판매자·작성자·구매자는 브라우저 입력을 믿지 않고 서버 세션의 회원 번호(`member:번호`)로 저장합니다. 학교와 학번 또는 이름이 같아도 회원 번호로 구별합니다.
- 내 판매글은 해당 회원이 새로 작성한 글만 표시합니다. 기존 `demo-seller` 예시 글은 그대로 공개 목록에 남으며 새 회원의 소유로 넘기지 않았습니다.
- 자신의 상품은 직접 구매 예약할 수 없습니다. 다른 회원이 예약하면 구매자와 판매자에게만 거래 정보가 보입니다. 거래 변경은 참여자, 결제 요청은 구매자만 가능합니다.
- 사장 회원가입·매니저 관리·관리자 목록 API의 기존 역할 검사를 유지했습니다. 가게 소유권·사장 전용 가게 편집 기능을 새로 만드는 범위는 포함하지 않았습니다.

## 기존 프로젝트에서 유지한 조건
- H2 메모리 DB입니다. 서버 종료 시 회원가입·판매글 등 변경 데이터가 초기화됩니다.
- 이메일 인증은 팀원 구현의 **시연 모드**입니다. 실제 메일은 보내지 않고 화면에 인증번호를 표시합니다. 실제 이메일 발송 기능은 팀원 원본에서도 미구현입니다.
- 학교 목록과 계정은 팀원 원본의 초기 데이터를 사용합니다. 마켓 지도·예시 상품은 기존 인하대학교 화면을 유지했습니다.
- Google 지도와 Toss 테스트 결제는 기존 환경변수 설정을 유지했습니다. 외부 키를 넣지 않았으며 실제 결제창·승인 성공은 이번 검증에 포함하지 않았습니다.
- 기존 설명은 `docs/통합전_README.md`에 보관했습니다. 그 안의 '로그인 미구현/예시 계정으로 쓰기' 설명은 통합 전 이력입니다. 현재 동작은 이 README가 기준입니다.
