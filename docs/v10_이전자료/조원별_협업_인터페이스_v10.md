# 조원별 협업 및 인터페이스 — v10 (2026-10-30)

## 반영 범위
v9 MyBatis 소스를 기준으로 학생 식별자·매너온도·거래 완료 후 평가를 추가했습니다. 기존 중고거래 첫 화면, 인하대학교 표기, 모임 탭 제거, 학생용 가게 화면을 유지합니다.

## 1. 회원가입·로그인 담당
- `student.unisno`: VARCHAR(50) 기본키 / Java String. 학번 앞의 0을 보존합니다.
- `student.temp`: INT NOT NULL DEFAULT 365 / Java Integer. 365는 36.5도입니다. 등록 시 생략하면 DB 기본값 365가 적용됩니다.
- StudentDto 기본 temp도 365입니다. 가입 저장은 StudentDao.insert를 사용할 수 있습니다.
- 로그인 성공 시 서버 세션에 `loginUnisno`(String)를 저장하세요. 대안은 `loginStudent`(StudentDto)입니다. 둘 다 있으면 loginUnisno를 우선합니다. 로그아웃 시 세션을 무효화하세요.
- 실제 인증 연동 후 `CAMPUS_DEMO_USER_ENABLED=false`를 설정해야 합니다. 기본값 true는 원본 v9의 demo-buyer 시연을 위한 설정입니다. UI에도 시연 계정임을 표시합니다.
- 이 수정본은 로그인·비밀번호 인증 기능 자체를 구현한 버전이 아닙니다. 기존 상품 등록/예약 Controller의 demo-seller/demo-buyer 고정값도 로그인 담당이 같은 세션 학번으로 교체해야 합니다.
- `sales.seller`와 `trade_orders.buyer`에 student.unisno를 저장해야 합니다. 평가 폼에서 평가자·상대 학번을 받지 않고 서버가 세션과 거래에서 결정합니다.

## 2. 거래 상태 관리(C) 담당
- 최종 완료 시 `trade_orders.status='COMPLETED'`로 저장하는 것을 권장합니다. 평가 조회와 저장은 `거래완료`도 허용합니다. PAID는 평가 가능한 완료 상태가 아닙니다.
- 기존 TradeService.complete는 주문 COMPLETED 및 상품 거래완료를 한 트랜잭션에서 처리합니다. 외부 담당 코드도 상품 상태를 함께 맞추면 목록과 DB가 일치합니다.
- 카드 상세는 주문이 COMPLETED/거래완료이면 평가 영역을 표시합니다. `/trades/selectOne?id=주문번호` 하단에서도 자동 활성화됩니다.
- 평가 전 거래 행과 대상 학생 행을 잠그고 저장합니다. 거래당 각 당사자가 상대방을 한 번씩 평가할 수 있으며 중복 UNIQUE 제약이 있습니다. 완료 전·비당사자·등록되지 않은 학생·중복 평가를 서버에서 거절합니다.

## 3. 화면·프론트(YS) 담당
- Thymeleaf: `src/main/resources/templates/trades/selectOne.html` 하단 폼.
- 카드 상세/지도·결제 영역: `static/preview/manner-rating.js`의 renderTradeRating. app.js, integrations-live.js에서 호출합니다.
- GET `/api/trades/{id}/rating`: rating(가능 여부/현재 온도/안내), csrfToken, demo 반환.
- POST 같은 주소: JSON `{ "feedback": "GOOD" }` 또는 BAD. GET 응답의 csrfToken을 `X-CSRF-Token` 헤더에 넣고 같은 세션 쿠키를 유지합니다. 잘못된 토큰은 403입니다.
- HTML POST `/trades/rating`: id, feedback, csrf. 성공하면 해당 상세로 이동합니다.
- 원래 화면 디자인을 유지했으며 평가 결과는 student.temp를 반영한 sale_listing VIEW를 통해 카드 판매자 온도에도 표시합니다. 기존 seller_temperature는 학생 미등록 데이터의 표시 호환용입니다.

## 4. MyBatis 작성 순서와 파일
StudentDto / MannerRatingDto → StudentDao / MannerRatingDao → mappers/StudentDao.xml / MannerRatingDao.xml → MannerRatingService → MannerRatingController / MannerRatingApiController → trades/selectOne.html.
TradeDto, TradeDao.xml, TradeController, RatingSession, ApiErrorAdvice도 연결했습니다. SQL은 XML Mapper에 둡니다.

## 5. 아직 조별 합의가 필요한 정책
임시 정책은 좋아요 +1(0.1도), 아쉬워요 -1(-0.1도), 온도 범위 0~1000(0~100도)입니다. application.properties의 campus.rating.good-delta / bad-delta에서 바꿀 수 있습니다. 조장님이 증감량을 지정한 것은 아니므로 이 기본값은 합의 후 조정하세요. 저장한 평가 delta는 실제 증감량입니다.

## 6. 실행·검증
ZIP 전체 압축 해제 → 실행하기.cmd → http://localhost:8080/ . Windows 64비트 실행용 Java와 갱신된 JAR를 포함합니다. 소스 빌드는 JDK 25와 Gradle 의존성 다운로드가 필요합니다.
완료된 예시: http://localhost:8080/trades/selectOne?id=demo-completed-1 . 미완료 예시: id=demo-reserved-2 . 서버 재실행 시 메모리 H2 데이터가 초기화됩니다.
테스트: gradlew.bat test bootJar. 기존 기능 9개 + 평가 기능 8개를 실행했습니다. 실제 지도·토스 테스트는 본인 키가 필요하며 이번 전달본에는 비밀 키가 없습니다. 실제 결제·송금·정산 기능은 포함하지 않습니다.

## 7. 기존 DB와 통합 시
schema.sql 및 docs/sql/schema-h2.sql·schema-mysql.sql은 새 DB 생성용입니다. 기존 데이터가 있는 DB에 그대로 재실행하지 마세요. 기본 실행은 새 메모리 H2이므로 외부 DB를 자동 변경하지 않습니다.
로그인 조원이 이미 student 테이블을 만들었다면 새로 만들지 말고 unisno 문자형/기본키, temp 정수/기본값365/NOT NULL을 확인하여 합치세요. 거래 상태 CHECK에 거래완료를 추가하거나 COMPLETED로 통일하고 manner_ratings 테이블 및 sale_listing VIEW 변경분을 반영해야 합니다. 다른 회원 컬럼을 삭제하거나 덮어쓸 필요는 없습니다. 기존 학번 데이터 및 sales.seller·trade_orders.buyer와의 연결을 확인한 후 백업한 DB에 적용하세요.

## 전달 제한
웹 서비스의 기존 가짜 사용자 CRUD는 실사용자 인증·권한까지 구현한 것이 아닙니다. 이번 평가 기능의 세션 연결 규칙을 제공했으며 전체 서비스 실사용자 전환은 로그인 담당 통합 작업이 필요합니다. 공개 링크에 현재 돌아가는 별도 이전 서버는 이 ZIP으로 자동 갱신되지 않습니다.
