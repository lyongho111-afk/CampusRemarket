# v10 실제 로그인 통합 후 작업 인계서

현재 기준은 이 ZIP의 campus-remarket 프로젝트 하나입니다. 이전 v9 로그인 통합본과 v10 평가 작업본을 병합했습니다. 최초 ZIP/IdeaProjects 원본은 보존했습니다.

완료: 실제 회원가입/로그인, JPA Member와 MyBatis student 연결, 실제 학번 String으로 seller/buyer/평가자/상대방 통일, 로그인 세션 loginMemberId+loginUnisno, 시연 대체 계정 제거, 내 판매글 및 거래 권한 연결, 거래 완료 후 양방향 평가와 온도 반영, 0도/앞자리0/동시 중복 검증, 실행 JAR 재빌드 및 교체.

student.unisno VARCHAR(50) PK / temp INT DEFAULT 365를 유지했습니다. member_id BIGINT UNIQUE를 추가해 다른 회원에게 같은 학번을 자동 연결하지 않습니다. 학교별 동일 학번 허용 여부는 조별로 논의하고 복합키 정책을 정해야 합니다. 직원 계정은 학생 거래 주체로 사용하지 않습니다.

회원 담당 소스 변경은 MemberService.java와 MemberController.java의 학생 연결/세션 처리이며 member.js의 이동 주소 1곳 변경도 유지했습니다. 정확한 전체 diff와 원본 해시는 docs를 참조하세요.

평가 증감량은 임시 기본 GOOD +1, BAD -1(±0.1도), 범위 0~1000입니다. 조별 정책 합의 후 campus.rating.good-delta / campus.rating.bad-delta를 조정하세요. 실제 이메일은 시연 모드이며 발송 구현은 남아 있습니다. 외부 지도/토스 키는 포함하지 않았습니다.

기존 demo-seller/demo-buyer 데이터는 보존하지만 실제 회원에게 할당하지 않았습니다. 평가 확인은 두 학생 계정으로 새 거래를 생성해서 진행하세요. 서버 재시작 시 메모리 DB가 초기화됩니다.

전체 테스트 24개 성공. 최종 JAR 실제 회원가입→거래완료→평가→36.6도 실행 확인 성공. JS 완료 상태/0도/학번 검사 성공. UI 전체 브라우저 클릭 및 외부 결제 성공까지 검증한 것으로 표현하지 마세요.

후속 소스 수정 후 gradlew.bat test bootJar를 실행하고 build/libs의 새 bootJar를 app/campus-remarket.jar에 반드시 복사한 뒤 재시작하세요. 실행하기.cmd는 app의 JAR를 실행합니다. 공개 공유 주소는 해당 주소의 실행 프로세스까지 갱신해야 바뀝니다.
