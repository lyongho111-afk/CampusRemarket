# v13 실행 및 확인 방법

## 실행

1. ZIP 전체를 새 폴더에 풉니다. ZIP 안에서 실행하거나 app 폴더만 따로 옮기지 마세요.
2. 기존 8080/8081/8082 서버가 실행 중이면 기존 실행 창에서 종료합니다. 포트 충돌 시 무관한 프로그램을 자동 종료하지 않습니다.
3. 세사이트_모두실행.cmd를 더블클릭합니다. 포함된 Java 25 실행환경을 사용하므로 실행만 할 때는 Java 설치가 필요하지 않습니다.
4. 시작 완료 안내 후 아래 주소를 브라우저에서 엽니다. 실행 창을 유지해야 합니다.

| 화면 | 주소 | 시연 계정 |
| --- | --- | --- |
| 학생 사이트 | http://localhost:8080/ | 기존 학생 계정 사용 |
| 사장센터 | http://localhost:8081/ | owner1 |
| 매니저 | http://localhost:8081/ | manager1 |
| 관리자 | http://localhost:8082/ | admin1 |

사장·매니저·관리자 시연 비밀번호: campus1234!  
로그인 화면의 시연 계정 입력 버튼은 입력만 채웁니다. 로그인 버튼을 눌러야 합니다.

한 번에 실행하지 않을 경우 실행하기.cmd로 공통 서버를 먼저 켠 뒤 사장사이트_실행.cmd와 관리자사이트_실행.cmd를 실행합니다. 종료는 각 실행 창에서 Ctrl+C를 사용합니다. 세사이트_모두실행.cmd는 이번에 시작한 세 서버만 관리합니다.

## 기능 확인 순서

1. 사장센터 owner1 로그인 → 대시보드에서 소개 준비 점검을 확인합니다.
2. 영업 관리 → 여유 공간을 수정 → 다른 메뉴를 클릭 → 미저장 확인에서 취소하면 입력이 남는지 확인합니다.
3. 운영 정보 저장 → 변경 이력 조회 → 변경자·시각·변경 전후를 확인합니다. 검색·기간·정렬 후 CSV 저장으로 결과를 내려받습니다.
4. 같은 사장 계정으로 두 탭을 열어 두고 첫 탭에서 먼저 저장합니다. 두 번째 탭에서 예전 정보로 저장하면 충돌 안내가 나오고 입력이 남아야 합니다.
5. 관리자 admin1 로그인 → 가게 관리 → 상세·배정에서 정보를 검토합니다. 공개 중지는 사유를 입력한 뒤 처리합니다.
6. 운영 처리 이력에서 관리자·가게·전후 값·메모를 확인합니다.
7. 사장센터 가게 정보 → 최신 정보 불러오기 → 관리자 안내에서 공개 중지 사유를 확인합니다.
8. 관리자에서 다시 승인·공개한 뒤 학생 사이트에서 가게가 보이는지 확인합니다.
9. 매니저 manager1로 로그인하면 영업 관리와 이력은 이용할 수 있고, 가게 기본 수정·매니저 관리는 제한되어야 합니다.

테스트 중 직접 저장한 값은 현재 서버 메모리에만 남습니다. 공통 서버를 다시 실행하면 기존 시연 데이터로 초기화됩니다. CSV는 다운로드한 파일이므로 서버를 꺼도 남습니다.

## 소스를 수정한 뒤 다시 빌드

JDK 25와 최초 의존성 다운로드용 인터넷 연결이 필요합니다. 실행용 runtime에는 컴파일러가 없으므로 별도 JDK가 필요합니다. 프로젝트 폴더에서:

~~~powershell
.\gradlew.bat test bootJar
node tools/verify-portal-ui.mjs
~~~

성공 후 실행 중인 서버를 종료하고 build/libs/campus-remarket-mybatis-0.0.1-SNAPSHOT.jar를 app/campus-remarket.jar로 복사한 뒤 다시 실행합니다. Node 검증은 개발 검증용이며 앱 실행에는 Node가 필요하지 않습니다.
