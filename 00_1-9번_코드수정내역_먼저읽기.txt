이 파일이 최종 통합 안내입니다. 이전 변경내역 문서는 작업 이력으로 보존했습니다.
이번 최종본의 좋아요는 브라우저 저장 방식이 아니라 DB 저장 방식입니다.

[빠른 확인]
1. 좋아요 UI: 반영 완료
2. 주소·좌표·지도: 구현 완료 / 자동 변환은 카카오 REST 키 설정 필요
3. 사장 학교 선택·저장: 반영 완료
4. 업체 업로드 사진 표시: 반영 완료
5. 계정 찾기·비밀번호 변경: 구현 완료 / 이메일 인증은 SMTP 설정 필요
6. 검색어 전체 삭제(X): 반영 완료
7. 공통 버튼·페이지 이동 아이콘: 반영 완료
8. 네 종류 좋아요·관심목록: DB 연동 완료 / 가격 변동 알림은 검토만 완료
9. 거래 약속 알림: 앱 내부 알림 및 모의 발송 테스트 완료 / 실발송은 계정 설정 필요

1. 학생 페이지 좋아요 UI
- 하트 버튼을 상품 이미지 위에서 카드 아래 영역으로 이동했습니다.
- 공개 좋아요 수와 눌림 상태를 표시하고, 관심 등록 별표 버튼을 분리했습니다.
- 상품 목록, 상세 화면, 작은 화면의 배치와 키보드 초점 표시를 정리했습니다.

2. 사장 회원가입 — 주소 및 위도·경도
- 카카오 주소 검색 API로 도로명/지번 주소를 좌표로 변환하는 서버 기능을 추가했습니다.
- 기존 주소 선택 팝업의 도로명/지번 선택값을 구분해 반영했습니다.
- 가입 시 주소 자동 검색 또는 지도 클릭/핀 이동으로 정확한 위치를 지정합니다.
- 가입 이후 사장센터의 가게 기본 정보에서도 위치를 보정할 수 있습니다.
- 가게 INSERT/UPDATE에 위도·경도를 반영하고 학생 지도에서 저장된 좌표로 표시합니다.
- 위치 수정 권한, CSRF, 저장 버전 및 변경 이력을 확인합니다.
- 적용 방식: 가입 시 자동 변환 + 수동 지정, 가입 후 보정도 함께 제공.
- 실제 카카오 키가 없으므로 외부 자동 검색은 아직 실서비스 검증 전입니다.
  현재 지도 직접 지정은 사용 가능합니다. 자동 변환은 모의 API 응답으로 검증했습니다.

3. 사장 회원가입 — 학교 정보
- 기존 학교 목록 API에서 학교를 불러와 선택하도록 추가했습니다.
- 회원 엔티티에 이미 있는 member.school_id 연관관계를 사장 회원에도 연결했습니다.
- 사장센터에 저장된 학교 이름을 표시합니다.
- 같은 의미의 학교 컬럼을 중복 추가하지 않았습니다.
- 기존 사장 회원의 학교를 임의로 배정하지 않았습니다.

4. 학교생활 — 실제 가게 사진
- 업체가 업로드한 사진을 가게 목록에 썸네일로 표시합니다.
- 상세 화면과 기존 업체 사진 데이터/파일 조회 경로를 사용합니다.
- 사진이 없으면 업종 아이콘, 사진 로딩 실패 시 대체 표시를 보여줍니다.
- 실제 가게 사진 파일이 등록되어야 실제 사진이 표시됩니다.

5. 로그인 — 아이디 찾기 및 비밀번호 변경
- 가입 이메일 인증 후 아이디/가입 유형 조회 및 비밀번호 재설정을 추가했습니다.
- 로그인한 계정은 현재 비밀번호 확인 후 새 비밀번호로 변경할 수 있습니다.
- 암호화 저장, 인증 만료·재요청/시도 제한, 변경 전 로그인 세션 무효화를 적용했습니다.
- 이메일 발송 계정이 없어 SMTP는 미설정 상태입니다. 실제 이메일 발송은 아직 하지 않았습니다.
- 이메일 발송 계정을 만든 뒤 SMTP 로그인/키와 인증한 발신 주소를 설정해야 합니다.
  비밀번호나 API 키를 공개 ZIP에 포함하지 않습니다.

6. 검색어 전체 삭제(X)
- 상단 물품/게시글 검색과 커뮤니티 안쪽 검색창에 X 버튼을 추가했습니다.
- 누르면 입력 전체를 지우고 검색 결과와 입력 초점을 갱신합니다.

7. 로그인·회원가입·추가·페이지 이동 버튼
- 공통 버튼의 녹색 계열, 둥근 테두리, 크기와 초점 표시를 정리했습니다.
- 학생·사장/매니저 페이지 이동에 학교/가게 아이콘과 설명을 함께 표시합니다.
- 기존 회원가입 HTML, member.js 및 기본 style.css 원본은 유지하고 확장 파일로 연결했습니다.

8. 좋아요 및 관심목록
- 판매글/일반 게시글/가게/댓글 네 종류에 좋아요 수와 등록·취소를 적용했습니다.
- DB 테이블 content_reactions와 조회 뷰 engagement_targets를 추가했습니다.
- 계정·대상 종류·대상 번호·반응 종류의 복합 기본키로 중복을 방지합니다.
- 같은 계정의 동시 요청을 DB 행 잠금으로 처리하고 변경 요청은 로그인/CSRF를 검사합니다.
- 관심 등록은 좋아요와 독립적이며 내 계정에서만 보는 목록으로 제공합니다.
- 전체/판매글/게시글/가게/댓글 분류, 24개 단위 이전/다음 이동, 원문 이동을 제공합니다.
- 관심 취소 시 목록에서 즉시 제거하며 삭제·비공개 콘텐츠는 목록에서 제외합니다.
- 이전 브라우저 저장소의 비회원 좋아요는 계정 소유권을 확인할 수 없어 자동 이관하지 않습니다.
- 가격 인상/인하 알림은 회의록의 '추후 개발 검토' 항목으로 문서화했으며 아직 구현하지 않았습니다.

9. 판매자 거래 약속 알림 및 비용 조사
- 기존 약속 알림 코드를 유지하고 검증을 보강했습니다.
- 구매자가 약속을 만들면 판매자의 앱 알림과 문자/이메일/카카오 발송 대기가 생성됩니다.
- 판매자만 알림 조회·읽음·재시도를 할 수 있으며 중복 예약의 알림 생성을 막습니다.
- 수신 끄기, 연락처 검증, 설정 누락, 모의 서비스 접수/거절, 실패 후 재시도를 테스트했습니다.
- 접수 완료한 채널은 재시도 요청으로 다시 발송하지 않는 것을 확인했습니다.
- 테스트는 모의 HTTP 서비스와 모의 메일 발신기를 사용하여 실제 발송 비용은 발생하지 않았습니다.
- 실제 이메일/휴대전화 수신 확인은 아직 하지 않았습니다. 현재 서비스 계정/키가 없습니다.
- 문자와 카카오는 SOLAPI 계정/발신번호 등록, 카카오는 채널/승인 템플릿이 추가로 필요합니다.
- 자세한 공식 요금 출처와 무료 이메일 후보는 '최신_좋아요관심목록알림_변경내역.md'에 있습니다.
- 현재 코드의 문자 채널은 약속 내용을 담는 LMS입니다. 단문 SMS 요금과 다릅니다.
- 외부 발송 기본값 NOTIFICATIONS_ENABLED=false를 유지합니다.

- 이번수정_변경내역.md: 이전 1~7번 작업 이력(좋아요는 이후 DB 방식으로 변경됨)
- 원본대비_소스변경.diff, 추가수정_소스변경.diff: 실제 파일별 코드 차이
- 변경파일_SHA256.json, 추가수정_변경파일_SHA256.json: 변경 파일 전후 검증값

[DB 및 실제 계정 설정 주의]
기본 DB는 기존 H2 메모리 방식입니다. 일반 재실행 시 초기화되는 기존 설정은 유지합니다.
소스 ZIP에는 현재 사용자 DB 데이터, 업로드 파일, 실제 비밀번호/API 키/로그를 넣지 않았습니다.
지속적인 데이터 보존은 영구 DB 구성으로 별도 전환해야 합니다.
이메일 계정을 준비한 뒤 실제 발송을 이어서 설정할 수 있습니다.
